## Problem Statement

The vault grew from about 300 notes to 1,328 in two weeks, and three parts of it did not scale:

- **Start context.** `hooks/vault-context.ts` injects Home.md (17.2 KB) and MEMORY.md (1.8 KB). The total is over Claude Code's hook output cap (about 10,000 characters), so Claude Code saves it to a file and shows a 2 KB preview. Since 8 Oct, 2,289 sessions got the preview: about 19 Home lines and none of MEMORY.md. The 150-line budget does not catch it, because lines run to 200 characters. A fixed-size index cannot hold a store that grows by about 3 Home-kind notes a day.
- **Run data in the wiki.** Episodes are 849 of 1,328 notes and 2,309 of 2,401 vault commits since 1 Nov. Each one is derived from the ledger, the issue store and git, but goes through the gates for curated notes. No surveyed repo puts run data in its curated store.
- **Recall.** The vault-recall hook ranks candidates by title and alias words only, then Jev judges the top 40. In the 7 days to 4 Nov (`vault misses --days 7`): 2,682 hook runs, 2,558 (95%) over the 40-candidate cap, 1.24 notes kept per run, and 25 vault notes read that recall never offered. Episode titles take candidate places by word coincidence.

## Model

claude-lane-stack keeps four layers apart. This plan maps each one onto aleph:

| Layer | claude-lane-stack | aleph after this plan |
|---|---|---|
| Curated facts | `.agents/memory/<id>.md` per repo, now one database on a hub | the vault `wiki/`, one store for all projects |
| Always-on facts | CORE block in AGENTS.md, 3,072 B cap, "N more: search" line | MEMORY.md plus the `core:` lines of the session's scope and `global`, 6,000 B cap |
| Derived index | `.cls/local-memory/memory-lexical.sqlite`, FTS5, not in git, rebuilt when missing | `<vault>/.index/vault.sqlite`, FTS5, gitignored, rebuilt when the vault HEAD moves |
| Run data | `~/.agents/usage`, `gate-events.jsonl`, outside the facts | `<factory>/episodes/`, `<factory>/monitor/`, outside the vault |

Recall follows claude-lane-stack's ranking (reciprocal rank fusion over several lists) and keeps Jev as the last step, which no surveyed repo has.

## Fixed

These do not move: the note schema except one new optional field (`core:`), `vault write` and its gates, the vault as one git repo pushed to `crsmithdev/aleph-vault`, Jev as the judge, the `vault-recall` Langfuse span, and MEMORY.md's content.

## Phases

Each phase lands on its own branch. The factory builds `proposal` items without approval (seen 4 Nov with aleph-1207), so these phases run by hand or with the factory paused.

### Phase 0: cap the start context now (no decision needed)

`hooks/vault-context.ts`:
- MEMORY.md first and in full.
- Then the Home lines whose note has the session's scope or `global`. The scope is the basename of the main checkout (`git rev-parse --git-common-dir`), so a worktree gets its repo's scope.
- Cut at whole lines so the total is at most 6,000 bytes. When lines are cut, the last line is `N more Home lines: vault recall --scope <scope>`.

Checks:
- A test with a fixture vault: an over-budget Home gives output of at most 6,000 bytes, MEMORY.md whole, no line cut in the middle, and the "N more" line.
- Live: a `claude -p` session started in `~/aleph` with `CLAUDECODE` unset writes no new `hook-*additionalContext.txt` file.

Time: about 15 minutes. Phase 3 replaces the Home part.

### Phase 1: run data out of the vault (D2, D3)

- `jobs/lib/episode.ts` writes `<factoryDir()>/episodes/<episodeTitle>.md` directly, with no `vault write`, and keeps the newest 2,000 files.
- `jobs/lib/plan.ts` `recallEpisodes` reads that folder with the rule `recall --episodes` uses today (distinct query words, ties by title, top 3).
- `jobs/lib/factory.ts` reads episode titles from that folder for the report's seen list.
- `ui/api/memory-types.ts` and `ui/views/memory.js` count episodes from that folder.
- The vault: one commit moves `wiki/episodes/*` to `<factory>/episodes/`. `episode` leaves `FOLDERS` and the kinds, `recall --episodes` goes, and `vault/lib/templates.ts` drops the row.
- The monitor half is e6f9b7c (D3).

Checks:
- `vault/` and `jobs/` tests pass.
- The vault has no `wiki/episodes/`.
- A done goal in a fixture factory gets a file under `<factory>/episodes/` and no vault commit.
- The planner test finds 3 episodes from the new folder.
- After a day, `git -C ~/.aleph/vault log --since=1.day --oneline | wc -l` is under 50.

Time: about 30 minutes.

### Phase 2: derived index and fused recall

- `vault/lib/index.ts`: an FTS5 table over title, aliases, claim line and body, with scope, kind and updated as columns. It is stored at `<vault>/.index/vault.sqlite`, gitignored, and rebuilt when the vault HEAD differs from the HEAD stored in the index. `bun:sqlite` has FTS5 (checked 4 Nov).
- One ranker for `vault recall` and the hook. It uses reciprocal rank fusion (k = 60) over three lists: exact title and alias match, FTS5 bm25, and the session scope's notes by `updated`. The top 40 go to Jev, which keeps at most 3, as today.
- No repeats: the hook skips notes it already injected in this session and notes in the core. The list is in `~/.aleph/cache/recall-seen/<session>.json`. The hook deletes files there older than 7 days (PRINCIPLES.md rule 8).

Checks:
- Tests on a fixture vault: a note whose words are only in its body is a candidate, and a note injected once is not injected again in the same session.
- `vault misses --days 7`, a week after landing, against the numbers above: the capped share falls from 95% and unoffered reads fall from 25.
- Hook time stays under the 1,500 ms Jev timeout plus 100 ms.

Time: about 45 minutes.

### Phase 3: core lines and a generated Home (D1)

- Frontmatter `core: <one line, at most 160 characters>`. A note with `core:` is always on for its scope.
- `vault write` refuses a write that puts a scope's core over its share of the budget, and lists that scope's core lines ranked for demotion, as the Home budget refusal does today.
- `hooks/vault-context.ts` injects MEMORY.md plus the `core:` lines of the session scope and `global`, newest first, with the "N more" line from phase 0.
- Home.md is generated on each write: all decision, project, concept and entity notes by scope, then kind, newest first. It is for Obsidian and the UI Memory page. It is not injected and has no budget, and agents never edit it.
- Remove what the generated Home replaces (PRINCIPLES.md rule 5): `consolidate`, `planHome`, `homeCandidates`, the Home line budget in `budgetFindings`, and the `orphan` warning for a note with no Home line.
- Backfill: an agent writes `core:` lines for the decisions in force among the 140 current Home lines, within budget, through `vault write`. Chris can edit or remove any of them in Obsidian; nothing waits for him (PRINCIPLES.md rule 2).
- VAULT.md: Chris edits the read order, the layout table and the frontmatter block.

Checks:
- Tests: a core write over budget is refused with a ranked list; Home is the same after two writes in either order.
- Live: as in phase 0.

Time: about 30 minutes, plus Chris's backfill pick.

### Phase 4: decay by use (log now, act in 30 days)

- A note counts as cited when the session reads its file after recall offered it. Langfuse already has both; `vault misses` reads them.
- After 30 days of data, the staleness window counts from the last citation, not from the last recall return (`.recall.json`). A core line with no citation in 90 days is proposed for demotion. Nothing is deleted.

Check: `vault lint` names the uncited core lines on a fixture with a fake Langfuse.

Time: about 20 minutes, after 30 days.
