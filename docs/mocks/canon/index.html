Canonicalize a control

Mock · 2026-11-20

The loop

  1. Select. In annotate mode, press a control on any page and choose Canon (key C).
  2. Extract. An agent opens the page in playwright and reads the control's computed style, DOM shape, text and source helper. It names the component class.
  3. Review. Each feature comes back as one claim, classed against docs/design.md: matches, new or conflicts. You keep, drop or edit each one. Approve writes the doc entry and its specimen.
  4. Apply. The agent lists the controls that match the canon: exact ones by helper call site, similar ones by a crawl. You confirm the similar ones and pick what to fix. A job fixes them on a branch and posts before and after shots.
  5. Guide. #/design lists each canon with its specimen, its features, where it is used and what breaks it. In annotate mode, hover a control to see its canon.

Fixed

  • Notes: the canon request is a note of kind canon in ~/.aleph/annotations.json, through shelf note. No new store.
  • Doc: docs/design.md stays the one place a rule is written. The guide page reads it, as #/design does now.
  • Code: a canon names one helper. Apply moves look-alikes onto that helper, so the fix is in one place.
  • Changes: every doc or code change is a branch and a job, so Deny or Discard drops it.

Example

Every step of this mock follows one control: the Show toggle of the Herald card's Active pane, ui/views/now.js:212. It is a seg(), and the doc has no Segmented control entry: its rules sit inside Filter bar and Tabs.
