Aleph

A personal agent that lives on your box, answers on Telegram, remembers things, and does coding work by driving the Claude Code CLI in a worktree. The daemon owns the conversation; claude is what it reaches for when the work is code.

Six scenes

What using it looks like

Hypothetical, and the point of the design: everything below is the target for M0–M4, and none of it runs yet. The mechanism sections after these scenes exist to make exactly these six things true.

01

A bug you found at your desk

terminal · ~/aleph-next
aleph do
$ aleph do "reindex dies on a torn last line — skip it and warn instead" job 7f3a · worktree .worktrees/job-7f3a · branch job/7f3a ▸ Read src/core/eventlog.ts ▸ Edit src/core/eventlog.ts ▸ Bash bun test tests/unit/eventlog.test.ts → 12 pass done · 2 files · +31 −4 · 12 tests pass $ aleph diff 7f3a $ aleph land 7f3a merged job/7f3a into main (squash) · worktree removed

aleph do is the conversation with the small talk skipped — the same code path as asking in chat, minus the asking.

03

Picking the remote session up locally

terminal · later that evening
aleph jobs · aleph attach
$ aleph jobs 7f3a landed 2h ago aleph-next reindex torn-line guard 91c2 waiting 18m ago aleph-next cap job stream log at 20MB a0d7 running 4m ago dotfiles migrate to fish $ aleph attach 91c2 cd ~/aleph-next/.worktrees/job-91c2 claude --resume 3f0e2c81-… ← interactive, full history, your skills

The job was a Claude Code session all along, so attaching isn't an import — it's the same session, with its transcript, its CLAUDE.md and its skills. While you're attached the daemon marks the job attached and won't spawn anything on that session id: two processes on one session id interleave writes into one transcript, which is measured behaviour, not a worry.

04

It speaks first, but only with something to say

[[cron]] at = "07:30" prompt = "morning: overnight job outcomes, anything waiting on me, today's calendar" [[cron]] at = "02:00" prompt = "run the aleph-next suite in a scratch worktree; message me only if it fails" quiet = true # silent unless the turn calls notify()

A scheduled turn runs with dispatch_code removed from its tool set, so the 2am run can test but never start unattended work of its own.

05

It remembers, and the memory reaches the work

telegram · then a week later
telegram
youremember: bun, never npm. and i squash-merge everything.
alephnoted (2 memories · aleph memory to review)
you… a week later, different repo … add a changelog script
alephjob c41f · dotfiles · branch job/c41f brief includes: "package manager is bun; merges are squashed"

Memories reach a job as facts about you inside a delimited block, never as system-prompt instructions — and every write is echoed back at you, so a poisoned memory is visible rather than silent.

06

What it declines

telegram
telegram
youpush that to prod
alephi don't have a deploy tool, and jobs run without push credentials. i can open a PR, or print the command for you to run.

The refusal isn't a policy the model was asked to follow. There is no deploy tool in the table, and the job's environment has no credential to push with.

Approval

Jobs

A job is a worktree with a life cycle

Features

Six things it does, and what bounds each one

aleph pair

Pairing before anything

An unknown chat gets one line telling it to send the code from aleph pair. Five wrong codes locks that id out; group chats are refused. Without this the bot handle is the credential.

remember · recall

Memory you can read

One fact per markdown file, written by the agent, listed by aleph memory. Injected as facts, never as instructions.

dispatch_code

Jobs that cannot publish

A worktree, acceptEdits, and an environment with no push credential and no agent socket. A job can commit. Only you can land.

gate()

Approval in plain code

Real arguments, live rules, a timeout you choose, default deny for anything unknown — and a line in the event log for every decision.

aleph attach

Remote work, finished locally

Any job resumes as an ordinary interactive Claude Code session in its worktree, because that is what it always was.

cron · schedule

Scheduled turns, fenced

Scheduled prompts run without dispatch_code, are shown to you when written, and quiet jobs stay silent unless they call notify().

State

Everything it knows is a file

~/.aleph-next/ soul.md identity, prepended to every chat turn config.toml pairing · channels · models · gate rules · cron conversations/*.jsonl the loop's own transcript — ground truth memory/*.md one fact per file, agent-written, human-readable jobs/<id>/ task.md · state.json · stream.jsonl (capped, rotated) events.jsonl messages, gate decisions, job transitions, cron fires index.db FTS and indexes — delete it and it rebuilds

Files are truth and index.db is disposable. The rebuild skips a torn final line and warns, rather than failing the whole reindex — which is also the bug in scene 01.

Build order

Each milestone is usable on its own

  1. M0 The loop, aleph chat, remember/recall, the event log A local assistant that remembers across restarts
  2. M1 Telegram, pairing, throttled streaming You use it from your phone all week
  3. M2 dispatch_code, jobs, attach / diff / land / drop It fixes a real bug in this repo, end to end
  4. M3 The gate, approvals over Telegram, redaction Unattended turns are safe to leave running
  5. M4 Cron, schedule, quiet jobs It speaks first, usefully

Containment at M2 comes from the job design — worktree, no credentials, no landing — not from the gate. That is why the gate can arrive at M3 without M2 being reckless.

Posture

What this does not protect you from

no sandbox

A job runs as you

Same user, same disk, no container in v0. Every control here is a fence, not a wall — worth saying out loud, because Hermes says the same thing in its own security notes.

one principal

It answers to one person

Pairing admits your devices and nothing else. There is no multi-user model, no roles, and no plan for either.

not yet built

None of this runs

Every scene above is a target. The design's own rule is that nothing gets claimed as working until it has been run and watched.

Reference shape: Hermes Agent (Nous Research) — a gateway, an agent loop, file-backed memory and skills, cron, a SOUL. Aleph keeps that shape and hands the coding to claude. Full design: docs/design/aleph.md. The comparison that chose this shape: docs/design/aleph-shapes.html.
