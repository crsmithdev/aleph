Design note · 22 Aug 2026 v0 supersedes phase-1 · phase-2a

Aleph

A Hermes-shaped personal agent — one process you talk to from your phone — whose engine is the Claude Code CLI you already use at your desk. Chat and coding are the same code path with different knobs.

The mechanism

One turn, end to end

The daemon is a gateway, not a brain. It moves messages, keeps the session map, brokers approvals and writes the log. Everything model-shaped happens inside a claude process it spawns.

The only variable

Chat and coding are one code path

The safety story

Approval comes to whatever screen you're on

State

Everything it knows is a file you can read

~/.aleph-next/ soul.md identity, appended to every run's system prompt config.toml channels · contexts · cron · auto-allow rules memory/*.md one fact per file, written by the remember tool sessions/*.json thread → session id, context, transcript path jobs/<id>/ task, worktree, stream log, diffstat events.jsonl every message, spawn, approval, job, cron fire index.db FTS over the above — delete it and it rebuilds workspace/ a git repo; .claude/skills/ loads natively
Skills, not reinvented

They are Claude Code skills in the workspace. agentskills.io packs drop in unchanged, and the CLI loads them without Aleph knowing they exist.

Transcripts, not copied

Full conversation history already lives in ~/.claude/projects/<slug>/<uuid>.jsonl. Aleph points at it and indexes it.

Build order

Each milestone is usable on its own

  1. M0 Daemon, session map, aleph chat against a persistent claude -p, event log A multi-turn conversation at the desk that claude --resume picks up
  2. M1 Telegram gateway on the same path, progress messages The same conversation, from your phone
  3. M2 MCP server: remember, recall, notify · soul.md · context block It uses a fact on Tuesday that you told it on Monday
  4. M3 Approval broker, repo: contexts, dispatch and jobs "Fix the failing test" from the phone returns a branch you review
  5. M4 Cron and the schedule tool A morning briefing arrives without being asked
Scope

Not in v0, and one thing unproven

Deliberately absent

Voice notes. Discord, Slack, Signal. User modeling. Autonomous skill authoring. Remote and serverless backends. Subagent fan-out. A web UI. Each is shaped like M2 — add it the week it starts annoying you.

Unverified assumption

Half-resolved: a headless --session-id run is continued by a fresh claude -p --resume in the same cwd, same id. The interactive picker is still untested, and two processes on one session id were observed interleaving writes into one transcript — the daemon, not the CLI, has to enforce exclusivity.

The other shape

Shape B — the daemon is the agent

Same surfaces, same files, one boundary moved: the daemon runs its own agent loop and the Claude Code CLI appears exactly once — as the worker that writes code in a worktree. This is the more literal reading of "a Hermes-like system that uses the CLI for coding," and it is what Hermes itself does.

TradeoffA — CLI is the engineB — daemon is the agent
BillingSubscription quota, because it is Claude Code.Metered per token against an API key — unless the loop embeds the Agent SDK with your Claude Code credentials, which puts you back in A with extra steps.
Chat latencyProcess spawn per turn, or a long-lived process speaking a control protocol on stdin.One HTTP call. No process lifecycle at all on the chat path.
The approval gateA hook contract: 60s default timeout, config snapshotted at session start, prefix patterns that don't bound arguments, unclear coverage of MCP and subagent calls.A function. You see the real arguments, set your own timeout, edit rules live, and log the decision on the same line as the event.
Injection blast radiusChat context holds Web + Write and, in repo contexts, Bash. One poisoned page reaches a tool-using agent.Chat tools are six hand-written functions. The dangerous surface is confined to jobs, in worktrees, without push credentials.
Compaction and historyFree, and battle-tested.Yours to build: windowing, summarization, token accounting, retries. This is the bulk of the new code.
Skills ecosystemSkills, CLAUDE.md, MCP, plugins apply to every turn.Only inside coding jobs. Chat gets whatever you write.
Desk handoffAny conversation resumes with claude --resume.Only jobs resume. The chat itself lives in your store, not the CLI's.
Session racesReal: two processes on one --session-id interleave writes into one transcript, with no lock in the CLI. The daemon must enforce exclusivity.Not a category. Each job is one process; chat has no CLI session.
Failure isolationOne runtime, one failure domain. A wedged process is also your chat.A wedged job doesn't touch chat.
ObservabilityThe CLI traces itself, locally, per process — nothing correlates it to your events.You emit the spans, so Phase 1's OTel and Langfuse work becomes useful again rather than deleted.
Code to write for v0Gateway, session map, MCP server, hook, job runner.All of that except the MCP server and hook, plus the loop — call it the larger half.
B wins if

You want the approval gate to be real code rather than a hook contract, you want chat to survive a wedged coding job, you want cheap models for small talk, or you expect to outgrow what the CLI's turn model allows. It is also the honest Hermes port: Hermes is a daemon with its own loop, and the CLI would be one more tool in it.

A wins if

The subscription is how you want this billed, and you'd rather spend the year on what Aleph does than on rebuilding compaction, retries and streaming. A's cost is that its safety story rents a mechanism you don't control; B's cost is that you now own an agent loop forever.

Reference shape: Hermes Agent (Nous Research) — gateway, agent loop, file-backed memory and skills, cron, SOUL.md. Aleph keeps the shape and swaps the loop for claude. Full design: docs/design/aleph-v0.md.
